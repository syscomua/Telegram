# Настройки форка: формат хранения

Возможности форка (избранная лента, локальные группы чатов) хранят настройки
в одном JSON-документе на аккаунт Telegram. Формат рассчитан на будущую
синхронизацию между устройствами и на клиент для ПК: две копии документа
сливаются по отдельным записям, без потери изменений.

Код: `TMessagesProj/src/main/java/org/telegram/messenger/ForkSettingsStore.java`.

## Где лежит на Android

Файл настроек приложения `fork_settings` (SharedPreferences,
`/data/data/<пакет>/shared_prefs/fork_settings.xml`), ключ `account_<userId>`,
где `userId` — id пользователя Telegram (не номер слота аккаунта в приложении).
Значение — строка с JSON-документом.

Документ не лежит в базе сообщений `cache4.db`: её клиент стирает при «Очистить
кэш», сбросе и выходе из аккаунта.

## Документ

```json
{
  "v": 1,
  "t": 1793180000000,
  "groups": {
    "1834092211": {"title": "Семья", "order": 1, "t": 1793170000000},
    "605112876":  {"title": "Старая", "order": 5, "t": 1793175000000, "deleted": true}
  },
  "members": {
    "945518395":  {"g": 1834092211, "t": 1793171000000},
    "-1001234":   {"g": 0, "t": 1793172000000}
  },
  "feed": {
    "-3547907703": {"added": 1793055370, "t": 1793055370000},
    "-1181169156": {"added": 1793055743, "t": 1793176000000, "deleted": true}
  }
}
```

Поля верхнего уровня:

| Поле | Тип | Смысл |
|---|---|---|
| `v` | int | версия формата, сейчас `1` |
| `t` | int64, мс | время последней записи документа |
| `groups` | объект | группы чатов, ключ — id группы |
| `members` | объект | в какой группе чат, ключ — id диалога |
| `feed` | объект | каналы избранной ленты, ключ — id диалога |

Общие правила для записей:

- `t` — время последнего изменения записи, мс с 1970-01-01 UTC, часы устройства.
- `deleted: true` — запись удалена. Удалённые записи не стираются, иначе при
  слиянии с другой копией они вернулись бы.
- Неизвестные поля нужно сохранять как есть: их может добавить более новая версия.

### groups

Ключ — id группы, случайное целое от 1 до 2147482646, строкой. Случайное, чтобы
группы, созданные на разных устройствах, не совпали номерами.

| Поле | Тип | Смысл |
|---|---|---|
| `title` | string | название, до 32 символов |
| `order` | int | место в списке групп, по возрастанию |
| `t` | int64 | время изменения |
| `deleted` | bool | группа удалена (необязательное) |

На Android группа показывается как папка с номером `1000 + id`, сервер Telegram
её не видит.

### members

Ключ — id диалога в нумерации Android-клиента: пользователь — положительный id,
группа или канал — отрицательный (`-chat_id` для старых групп, `-channel_id` для
каналов и супергрупп, как в `TLRPC.Dialog.id`).

| Поле | Тип | Смысл |
|---|---|---|
| `g` | int | id группы; `0` — чат убран из групп |
| `t` | int64 | время изменения |

Чат состоит максимум в одной группе. Если группа `g` удалена или отсутствует,
чат считается без группы.

Секретные чаты свои на каждом устройстве: при синхронизации их записи
(id секретного чата, см. `DialogObject.isEncryptedDialog`) передавать не нужно.

### feed

Ключ — id канала как диалога (отрицательный).

| Поле | Тип | Смысл |
|---|---|---|
| `added` | int, секунды | когда канал добавлен в ленту; по нему лента сортирует список |
| `t` | int64 | время изменения |
| `deleted` | bool | канал убран из ленты (необязательное) |

## Слияние двух копий

Для каждой секции и каждого ключа берётся запись с бо́льшим `t`. При равном `t`
приоритет у удаления. Запись, которая есть только в одной копии, переносится
как есть. После слияния `v` — максимальная из двух, `t` — время слияния.

## Что не входит в документ

Настройки устройства, которые синхронизировать не нужно, лежат отдельно:
`favorite_feed_settings` → `auto_scroll` (прокручивать открытую ленту к новым постам).

## Переход со старых файлов

Сборки до этого формата хранили данные в `local_groups` (`groups_<userId>`) и
`favorite_feed` (`channels_<userId>`). При первом чтении документа, если его ещё
нет, данные переносятся оттуда: группы получают случайные id, всем записям
ставится время переноса. Старые файлы не трогаются.
