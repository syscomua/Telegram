# План: чат-заглушка «Избранная лента» в Telegram для Android

## Идея

Пользователь отмечает каналы как «избранные». В списке чатов появляется
виртуальный чат-заглушка **«Избранная лента»**. Если его открыть, внутри будут
все посты из избранных каналов, отсортированные по дате, как в обычном чате.

Сообщения никуда не копируются и не пересылаются. Заглушка хранит только
**ссылки на сообщения**, то есть пары `(id канала, id сообщения)`. Сами сообщения
уже лежат в локальной базе клиента.

Заглушка существует только в нашем клиенте, сервер о ней не знает. Сделать её
настоящим контактом Telegram нельзя: настоящему чату сообщения доставляет сервер.

## Контекст

- Код: форк `syscomua/Telegram` (апстрим `DrKLO/Telegram`, версия 13.1.1 (7237)).
  В `syscomua/firmware` он подключён сабмодулем `telegram-android/`.
- Ветка разработки в форке: `feature/favorite-feed`.
- Исходники приложения: `TMessagesProj/src/main/java/org/telegram/`
  (`messenger/` — логика и хранилище, `ui/` — экраны).
- Апстрим-файлы правим минимально: новую логику кладём в новые классы, в
  существующие добавляем только точки подключения. Так проще подтягивать
  обновления Telegram.

## На что опираемся в существующем коде

| Что нужно | Что уже есть в клиенте |
|---|---|
| Виртуальный чат в списке | **«Архив»**: это тоже ненастоящий чат с особым id (`DialogObject.makeFolderDialogId`, `DialogObject.isFolderDialogId`) и типом `TLRPC.TL_dialogFolder`. Создаётся в `MessagesController` и `MessagesStorage`, рисуется в `ui/Cells/DialogCell.java`, обрабатывается в `ui/Adapters/DialogsAdapter.java` и `ui/DialogsActivity.java`. |
| Все сообщения в одном месте | Таблица `messages_v2(mid, uid, date, data, …)` в `MessagesStorage`. `uid` — id чата (для канала `-channelId`), `data` — сериализованное сообщение. |
| Быстрая выборка по каналам и дате | Индекс `uid_date_mid_idx_messages_v2 ON messages_v2(uid, date, mid)` уже существует. |
| Подгрузка истории канала с сервера | `MessagesController.loadMessages(...)` и `TL_messages_getHistory`. |
| События о новых, удалённых и изменённых сообщениях | `NotificationCenter`: `didReceiveNewMessages`, `messagesDeleted`, `replaceMessagesObjects`. |
| Отображение сообщения | `MessageObject` + `ui/Cells/ChatMessageCell.java`. |
| Работа с базой в фоне | `MessagesStorage.getStorageQueue()`, результат в UI через `AndroidUtilities.runOnUIThread`. |

## Этапы

Каждый этап — отдельный коммит или PR в ветке `feature/favorite-feed`.
После каждого этапа приложение собирается и проверяется на телефоне.

### Этап 1. Список избранных каналов
- Новый класс `messenger/FavoriteChannelsController.java`: наследник `BaseController`,
  по одному экземпляру на аккаунт (`getInstance(int account)`).
- Хранение локально, отдельно для каждого аккаунта: свой файл настроек `favorite_feed`,
  ключ `channels_<userId>` (`PrefsFavoriteChannelsStore`).
  _Изменено при реализации:_ сначала планировалась таблица `favorite_channels` в базе
  `MessagesStorage` с подъёмом `LAST_DB_VERSION`. От неё отказались: эту базу клиент
  стирает при «Очистить кэш», сбросе и ошибках миграции, и список пропадал бы. К тому же
  свой номер версии базы конфликтовал бы с каждым обновлением апстрима. Ключ по id
  пользователя, а не по номеру слота аккаунта, поэтому после выхода и повторного входа
  список сохраняется, а другой аккаунт в том же слоте его не видит.
- Хранилище вынести за интерфейс (`FavoriteChannelsStore`), чтобы позже можно было
  подключить синхронизацию между устройствами.
- API контроллера: `isFavorite(did)`, `add(did)`, `remove(did)`, `getAll()`.
- Новое событие `NotificationCenter.favoriteChannelsUpdated`.
- Пункт меню «Добавить в избранную ленту» / «Убрать из избранной ленты»:
  - в меню (⋮) экрана канала: `ui/ChatActivity.java`;
  - в меню (⋮) профиля канала: `ui/ProfileActivity.java`;
  - в действиях при долгом нажатии на канал в списке чатов: `ui/DialogsActivity.java`.
- Пункт показывается только для каналов: `ChatObject.isChannelAndNotMegaGroup(chat)`.
- Звёздочка у избранного канала в `ui/Cells/DialogCell.java`.

**Проверка:** канал отмечается и снимается из трёх мест, отметка сохраняется после
перезапуска и не видна в другом аккаунте.

### Этап 2. Чат-заглушка в списке чатов
- Особый id для заглушки, который не пересекается с реальными чатами и с архивом.
  Например, по образцу `makeFolderDialogId`: свой `isFavoriteFeedDialogId(did)`
  в `DialogObject`.
- Заглушка вставляется в список чатов закреплённой сверху (под архивом), если в
  избранном есть хотя бы один канал.
- Строка заглушки в `DialogCell`:
  - название «Избранная лента» и своя иконка-аватар;
  - превью и время берутся из самого свежего поста избранных каналов;
  - счётчик — сумма `unread_count` избранных каналов.
- Строка обновляется при новом посте в избранном канале и при событии
  `favoriteChannelsUpdated`.
- Свайпы, закрепление, архивирование, удаление и выбор нескольких чатов
  для заглушки отключены. В меню долгого нажатия только «Скрыть» и «Настройки ленты».
- Заглушка не должна попадать в пересылку, «Поделиться» и выбор чата в других местах
  (другие `DIALOGS_TYPE_*`).
- Тап открывает экран из этапа 3. До этого этапа — пустой экран с заголовком.

**Проверка:** заглушка видна в списке, показывает правильное последнее сообщение
и счётчик и не появляется в диалогах пересылки.

### Этап 3. Экран ленты внутри заглушки
- Новый `ui/FavoriteFeedActivity.java` (наследник `BaseFragment`), внешне как канал:
  шапка с названием «Избранная лента» и числом каналов.
- Источник данных — запрос к локальной базе на `getStorageQueue()`:
  ```sql
  SELECT uid, mid, date, data FROM messages_v2
  WHERE uid IN (<избранные каналы>)
  ORDER BY date DESC, mid DESC
  LIMIT 50
  ```
  Следующая страница загружается по курсору `(date, mid)` последнего элемента,
  а не через OFFSET. Сервисные сообщения (закреп, смена фото и т. п.) отфильтровываются.
- Список хранит пары `(uid, mid)` и создаёт `MessageObject` для отображения.
- Альбомы (`grouped_id`) собираются в один элемент, как в `ChatActivity`.
- Посты показываются стандартными `ChatMessageCell`. Над постом заголовок с
  аватаром и названием канала, тап по нему открывает канал.
- Тап по посту открывает `ChatActivity` канала на этом сообщении (`scrollToMessageId`).
- Пустое состояние: подсказка, как добавить канал в ленту.
- Свой экран, а не `ChatActivity`, потому что `ChatActivity` везде рассчитан на один
  чат, а переделывать его под несколько каналов слишком рискованно.

**Проверка:** открыли заглушку и видите посты всех избранных каналов строго по
убыванию даты. Прокрутка на 200+ постов вниз без дублей и пропусков. Тап открывает
нужное сообщение в канале.

### Этап 4. Подгрузка и живые обновления
- В локальной базе есть только то, что клиент уже загрузил. Для давно не открытых
  каналов там часто только последний пост. Поэтому при открытии ленты для каждого
  избранного канала подтягивается свежая история через `MessagesController.loadMessages`
  / `TL_messages_getHistory`, сообщения сохраняются в `messages_v2`, лента
  перечитывается.
- При прокрутке вниз, если в базе закончились посты какого-то канала раньше
  остальных, догружается его более старая история.
- Не больше 3–4 запросов одновременно, обработка `FLOOD_WAIT` с паузой.
- Pull-to-refresh сверху.
- Подписки на события:
  - `didReceiveNewMessages` — новые посты избранных каналов появляются сверху,
    с плашкой «N новых постов», если пользователь пролистал вниз;
  - `messagesDeleted` — пост удаляется из ленты;
  - `replaceMessagesObjects` — пост обновляется (правка, реакции, просмотры).
- Прочитанность: показанные посты помечают канал прочитанным до этого id
  (`MessagesController.markDialogAsRead`). Поведение отключаемое, по умолчанию
  включено. Счётчик заглушки из этапа 2 уменьшается.

**Проверка:** новый пост в избранном канале появляется в открытой ленте и в превью
заглушки без перезапуска. Удалённый или изменённый пост обновляется.

### Этап 5. Управление и полировка
- Экран «Настройки ленты»: список избранных каналов с удалением, переключатель
  «Помечать прочитанным при просмотре», «Показывать заглушку в списке чатов».
- Экспорт и импорт списка избранных в файл, чтобы не потерять его при переустановке
  или выходе из аккаунта.
- Если пользователь отписался от канала или потерял к нему доступ, канал остаётся
  в списке, не участвует в ленте и выделен в настройках.
- Строки в `TMessagesProj/src/main/res/values/strings.xml`
  (`LocaleController.getString(R.string.X)`), переводы на русский и украинский
  (`values-ru`, `values-uk`).

## Общие требования
- Никакой работы с базой в UI-потоке.
- Корректная работа с несколькими аккаунтами (`currentAccount`).
- Светлая и тёмная тема через `Theme.key_*`.
- Сборка: `./gradlew :TMessagesProj_App:assembleAfatDebug`. Для неё нужны свои
  `api_id`/`api_hash` с https://my.telegram.org в `BuildVars.java`. Ключи не коммитить.

## Состояние реализации (2026-10-26)

Все пять этапов в ветке `feature/favorite-feed`, по коммиту на этап. Проверено на
Galaxy Note10 Lite (Android 13, arm64) с реальным аккаунтом и одним каналом.

Отличия от плана:
- Хранение — не таблица в базе, а файл настроек (см. этап 1).
- Заглушка — не фальшивый `TLRPC.Dialog` с особым id, а отдельная строка адаптера
  (`DialogsAdapter.VIEW_TYPE_FAVORITE_FEED`, ячейка `Cells/FavoriteFeedCell`). Так она
  не попадает в хранилище диалогов, папки, пересылку и «Поделиться», а свой id в
  `DialogObject` не нужен. Скрытая заглушка возвращается при добавлении канала.
- История с сервера загружается через `MessagesController.loadMessages(fromCache=false)`,
  а не напрямую через `TL_messages_getHistory`: так сообщения сохраняются вместе с дырами
  (`messages_holes`) и сам канал не теряет сообщения.
- Pull-to-refresh своим жестом (в проекте нет `SwipeRefreshLayout`).
- Тап по медиа, ссылкам и видео внутри поста открывает пост в канале; проигрывателя и
  просмотра фото прямо в ленте нет.

Проверено: отметка канала из списка чатов, звезда на аватаре, сохранение после
переустановки, строка под архивом с превью и временем, обновление превью новым постом,
экран ленты с плашками каналов, прокрутка на десятки постов вниз без падений,
экран настроек.

Не проверено (нужны каналы с альбомами, второй аккаунт и т. п.): раскладка альбомов,
несколько каналов вперемешку, удаление и правка поста в открытой ленте, `FLOOD_WAIT`,
экспорт и импорт файла, отметка прочитанного, светлая тема, пункты меню в шапке канала
и в профиле.

Сборка для одного телефона (быстрее, только arm64):
`./gradlew :TMessagesProj_App:assembleAfatDebug -Pandroid.injected.build.abi=arm64-v8a`.
APK такой сборки помечен test-only, ставится через `adb install -r -t`.

- Отдельные уведомления для ленты.
